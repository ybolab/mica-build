# Board dossier: s905x5m

## Identity

X88 Pro X5M / BM201, Amlogic S905X5M (S7D), `MOS_ARCH=arm64`.
The board implementation is in `boards/s905x5m/`.

## Provenance

This mainline adaptation imports the board-owned implementation from
`board/s905x5m` at `e53c1cfd`. The final integration baseline is mainline `09c384cd`;
[PLAN-922](../plan/PLAN-922.md) records the contract changes.

- Kernel: hardkernel/linux at `9ea2aa831a585955dcb0e38a0bc3c63d2c690adc`,
  with its pinned common_drivers submodule, thirteen local patches, board DT
  and Seekwave sources. Input class: source plus firmware blobs.
- U-Boot: CoreELEC/u-boot at `5f7ac2b1dc4df2f466ed88c3958a8675873f8a1a`,
  with the local patch series, including installer receipt patches 0017/0018.
  Input class: source plus vendor boot-chain blobs.
- Seekwave userland: board-local vendor library and integration bridge,
  imported with the source branch; provenance and license notices remain in
  `boards/s905x5m/bsp/userland/`.
- Amlogic package blobs: BM201 recovery inputs from s905x5m-alpine
  `49618bed07508b77bb8e8e640e0faafc5c95ea9a`; the package blob README and
  SHA256SUMS record their exact bytes.

## Boot chain

BootROM loads the Amlogic vendor stages and patched U-Boot. U-Boot executes
the board boot script, selects the RAUC A/B slot, loads the kernel and DTB,
and supplies the dm-verity command line. The kernel mounts the immutable
root and systemd mounts the persistent storage tiers.

Redundant U-Boot environments occupy 64 KiB each at 120 and 124 MiB.
The bootloader lives outside the eMMC user-area GPT, in the hardware boot
area. It must not be modeled as cx3576's GPT raw-loader partition.
The inherited vendor signatures do not establish a MOS-controlled verified
chain from BootROM through the root filesystem.
The cx3576-specific `mos-boot-digest.env` protocol added during this adaptation
remains enabled for cx3576; the s905x5m boot script does not declare it.

## Storage media and layout

`LAYOUT_VERSION=2` declares twelve partitions in `boards/s905x5m/board.env`:
vendor reserved, vendor environment, two redundant environments, two boot
slots, two verity root slots, META, STATE, EPHEMERAL and DATA.

The SD image formats reserved partition 1 as a cfgload bridge. **The SD image
is not an eMMC whole-disk flashing image.** The dedicated eMMC package and
installer producer retain the different vendor-owned-region contract.
Kernel, U-Boot and userland build exports live under `_out/boards/s905x5m/`;
selected package boot exports live under `_out/s905x5m/boot/`.

## Console

The serial console is `ttyS0` at 921600 baud, with
`earlycon=aml_uart,0xfe07a000`. Confirm the connector and voltage against the
specific board's hardware record before wiring. HDMI output depends on the
vendor display initialization and the board kernel/DT.

## Peripherals

The board declares Wi-Fi and Bluetooth using the Seekwave SWT6621/EA6521QF
firmware and SDIO transport. Bluetooth uses the vHCI bridge, not a UART
attach helper. Its derived address persists in STATE-backed
`/var/lib/bluetooth/bdaddr`; BlueZ uses the hostname plugin for the name.

`BOARD_HWINIT_CONFS` maps audio to ALSA routing, wireless to rail/module
initialization, and Bluetooth to the bridge. The radio packages are selected
independently: declining Wi-Fi retains the shared SDIO transport if Bluetooth
still needs it. Ethernet, HDMI and USB support remain in the kernel/DT and
vendor initialization. No status LED or board recovery action is declared.
RTC retention and the full peripheral matrix need qualification on this image.

The BM201 front panel and MQTT reference application are default-off local
packages selected by `MOS_ROOTFS_COMPONENTS`. The panel reads the current
`/run/mos/timezone` value on each update. The reference application is refused
in production profiles and requires the MQTT feature packages.

## Recovery method

The SD image provides a removable boot path. The separate Amlogic eMMC
package and installer-card producers are documented in
`boards/s905x5m/bsp/uboot/README.md`. Installer selection and its persistent
receipt follow the inherited board state machine. Generating an installer
artifact does not qualify interruption recovery on a device.

No OS reset/recovery action is advertised by `BOARD_RECOVERY_ACTIONS`.
Power-cut recovery and A/B rollback must be re-run on the newly composed
image before release acceptance.

## Known limitations

Opaque Amlogic boot stages and radio firmware reduce auditability. No new
hardware qualification is implied by the inherited branch's historical
passes. The mainline configuration model uses documents under `/mos/config`
and `time.ntp.servers`; it does not migrate the old monolithic settings
file. Existing-device state compatibility requires a separate migration
procedure and validation.
