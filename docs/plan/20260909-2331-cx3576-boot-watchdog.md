## Context

Physical startup stops before Linux because the fixed FIT boot policy cannot
obtain or start its mandatory watchdog. The shipped configuration enables WDT,
WATCHDOG and DESIGNWARE_WATCHDOG. The watchdog device-tree node is enabled.
The missing RK3576 clock enable callback makes DesignWare probe return -ENOSYS.

## Proposal

Trace the pinned firmware driver and control device tree. Add the missing RK3576 watchdog clock gates, distinguish watchdog probe/start errors, and assert the required
node and driver in firmware acceptance. Service the armed watchdog in the
RockUSB idle loop and exercise the actual loop in regression coverage. Rebuild
the signed firmware and a complete
factory image using the current authenticated components, with truthful source
records. Keep the watchdog mandatory and preserve signed boot and attempt policy.

## Risks

Hardware clock/reset wiring and timeout support must match RK3576. A compiled
driver or a host fixture does not prove physical watchdog reset or Linux handoff.

## Scope

Board firmware/device-tree integration, focused regression checks and current
image delivery. No compatibility, partition resizing or unrelated release redesign.

## Alternatives

Skipping the watchdog would leave early hangs without bounded fallback and would
weaken the approved boot contract; fix hardware integration instead.
