## Context

SYSTEM currently occupies 2048 MiB at 18 MiB; DATA starts at 2066 MiB and has a
256 MiB factory minimum. U-Boot, flash preflight/readback and fixtures repeat the
fixed geometry. The board package embeds exact SYSTEM repart limits in rootfs;
reusing the previous root would violate the new layout. The package pool requires
one source stamp across all producers. Signed kernel/support content is independent
of partition length and may retain its existing authenticated source identity.

## Proposal

Set SYSTEM to 1024 MiB, move DATA to 1042 MiB, and retain its 256 MiB minimum.
The complete image becomes 1299 MiB including the unchanged firmware reservation
and GPT tail. Update fixed consumers and current documentation. Establish RED
for the new geometry, update implementation, rebuild firmware, the current ARM64
package pool and root, sign fresh deployment records, and assemble a timestamped
full image. Run offline, capacity, signature, complete readback and DATA-growth
acceptance with the actual packaged repart policy.

## Risks

Changing only the image or only firmware would prevent boot. A stale root repart
policy could request unintended SYSTEM growth. All three are rebuilt together.
Physical board startup and power-cut/watchdog qualification cannot be inferred
from offline checks.

## Scope

cx3576 board layout, firmware, flash tooling, focused tests, current layout docs
and a complete image. Other board sizes and component wire formats are unchanged.
No compatibility branches or in-place conversion are introduced.

## Alternatives

A larger SYSTEM is unnecessary for the measured approximately 150 MiB payload.
One GiB retains the required current, fallback and candidate capacity plus the
128 MiB reserve. Shrinking an existing image would leave signed runtime policy
stale; rebuild from the requested current layout instead.
