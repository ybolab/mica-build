## Context

The signed file deployment migration bypassed the complete native main loop
before CLI initialization and set the MOS variant's delay to -2. The base debug
variant still requests one second, which does not affect the shipped MOS build.
The user requests a durable explanation and restoration of the standard entry.

## Proposal

1. Remove the early main-loop hook and register the existing policy as the
   `mosboot` command. Configure native autoboot with a one-second any-key delay
   and `bootcmd=mosboot`. Verify the patched main loop with deterministic input
   and time, including timeout and immediate/delayed keypress cases.
2. Exercise the registered command through the existing firmware I/O fault
   harness. Preserve signed FIT enforcement, trial persistence, watchdog, and
   recovery behavior. Build the MOS loader and assert the resolved configuration,
   command symbol, and absence of device-tree console overrides.
3. Document the development console policy in the existing boot design. Package
   a candidate with the repaired HDMI kernel, run image/signature validation,
   review the scoped diff, and record evidence. Physical serial/display checks
   require a board and will not be inferred from software results.

## Scope

CX3576 MOS firmware configuration and command integration, focused C/shell tests,
and the requested documentation. No persistent environment command import,
alternative boot mode, kernel rebuild, or compatibility branch is introduced.

## Risks

A native interactive console intentionally permits local development commands.
Normal automatic boot and `boot` must retain required FIT verification and the
bounded deployment transaction. The recovery button is sampled when the signed
boot command starts after the countdown. CLI idle input must continue servicing
the watchdog through the native cyclic scheduler.

## Approval

The user's request to retain the standard entry, explain it, and modify the
firmware approves this implementation following the completed investigation.

## Result

Restored the unmodified native main loop and registered `mosboot`, with a
one-second any-key countdown and the standard `boot` command. Native behavior
and registered-policy fault tests passed after reproducing the original failures.
The actual MOS build, required FIT signatures and rejection cases, all 123
offline image checks, loader placement, and checksum passed. The related task
records the candidate containing the prior HDMI repair. Physical serial/display
acceptance remains untested. One unrelated existing pipefail lint finding in
`embed-trust.sh:15` is recorded explicitly; scoped review has zero findings.
