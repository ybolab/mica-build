## Traced contract and implementation

| Path in pinned vendor tree | Finding and bounded repair |
|---|---|
| `drivers/video/logo/logo.c`, `pnmtologo.c` | Late init disables lookup, and both pixel/palette arrays plus the descriptor occupy init sections. The board patch makes generated arrays const and permanent, retains the descriptor, and removes the late-init lookup cutoff and `__ref` escape. The existing nologo parameter still applies. |
| `drivers/gpu/drm/rockchip/dw_hdmi-rockchip.c` | RK3576 HPD reaches `repo_hpd_event` in work context, then `drm_helper_hpd_irq_event` and the output-poll callback. This existing IRQ/work route is retained. No periodic forced redraw is added. |
| `drivers/gpu/drm/rockchip/rockchip_drm_fb.c` | `rockchip_drm_output_poll_changed` calls the standard helper, then updates the negotiated viewport and fbcon on a real HPD event. Helper absence/error, no connected mode, deferred fbdev, loader protection, disabled polling and delayed hotplug for a DRM master do not force a display. |
| `drivers/gpu/drm/drm_fb_helper.c` | Headless initial probing returns `-EAGAIN` and defers fbdev registration; later attachment retries the initial configuration and registers the framebuffer. Existing-framebuffer HPD only resets CRTCs/mode; it does not redraw fbcon or update its visible pixel dimensions. No change to this generic helper is needed. |
| `drivers/video/fbdev/core/fbcon.c` | Registration, visible mode change, unblank and VT return ultimately enter `fbcon_switch`. The new draw path operates only on visible, empty tty1 in active text mode. It clears the framebuffer, draws the existing centered logo and returns zero so `redraw_screen` does not immediately cover it with blank text. Existing text buffers and graphics ownership retain precedence. Initial logo preparation also refuses tty2, including first fbdev registration while tty2 is active. |
| `drivers/video/fbdev/core/fbmem.c` | Existing palette conversion, centering, CPU-independent explicit count and imageblit code are reused. Logo preparation now rejects insufficient width as well as height, with the existing rotation semantics, so a mode too small for the bitmap falls back to normal text handling. |
| `drivers/tty/vt/vt.c` | `redraw_screen` selects the requested foreground VT, calls `con_switch` and draws text only when it returns nonzero; no forced `fg_console` selection is added. The established cursor default, getty/logind policy and authentication are unchanged. |

HPD takes the console lock before helper/client locks, releases helper/client
locks before fbcon callbacks, and takes the framebuffer lock around viewport and
VT updates. This avoids recursive helper-lock acquisition from `fb_set_par`.
All mapped text VTs receive the new viewport, including a hidden tty1, so a later
switch cannot restore stale dimensions. It does not allocate a second framebuffer
or add a userspace service. Existing vendor reconnect probing remains bounded by
the original framebuffer allocation; larger-than-allocation modes are not forced.

The only enabled generated logo is the existing CLUT224 bitmap after
`configure.sh`; the committed seed config intentionally has LOGO disabled before
the board delta enables it. No config or configure change is needed. No watchdog,
boot trust, system geometry, DATA layout, rootfs, reboot dispatcher, old package
support, encoder patch or image asset is changed.
