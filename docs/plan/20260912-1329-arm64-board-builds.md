## Context

Fresh x64 production and QEMU lifecycle acceptance are complete. ARM-specific
packages, kernels and firmware have not been built in this clean environment.
Signing inputs are available in ignored `meta/`; they must not rotate.

## Execution and verification

1. Verify/reuse amd64 builders and build pinned ARM64 builders with isolated
   BuildKit emulation. Preserve previous x64 package pools and evidence.
2. Compile shared ARM64 packages and native lifecycle executables once; compose
   the virt-arm64 root separately. Build/sign kernel/support, UEFI firmware,
   two deployments and the complete image. Run root smoke and real QEMU checks.
3. Build CX3576 kernel and U-Boot with existing public trust anchors; add board
   packages, compose its root and sign/assemble the complete image.
4. Build S905X5M kernel, U-Boot and required board userspace; compose and sign
   its complete image. Verify artifact identity, signatures, layout and sizes.
5. Record exact successes, failures and physical requirements. Keep 30-minute
   progress checkpoints in the active conversation.

## Limits

No host toolchain installation, automatic host binfmt changes, fixed resource
quotas, key replacement, compatibility layer, fleet or OCI activation.
Identify available bench targets before physical flashing. Missing vendor
inputs and unexecuted hardware checks remain explicit gaps.

its bootloader recovery package. Static verification: virt-arm64 104 pass with
one undeclared-radio skip, CX3576 126/126, S905X5M 105/105. virt-arm64 QEMU API
149/149 and real reboot/persistence/poweroff passed. The crun qemu-user limit
was closed in the full virt-arm64 guest; physical board acceptance is pending.

Fixed actual boot-tool architecture, PE extraction, runtime resource selection,
BlueZ path, S905X5M Bluetooth payload and device-mapper selection defects. Kept
