## Description

The physical cx3576 reports `MOS FIT recovery: required boot watchdog unavailable`
before loading Linux. Diagnose the shipped configuration and control device tree,
repair the mandatory watchdog integration and rebuild a complete current image.
The existing P10 implementation and full-image delivery authorization applies.

## ActiveForm

Rebuilding firmware after the pinned driver regression passes.

## Verification

Reproduce the missing watchdog integration on the shipped artifact, establish
regression coverage, verify the rebuilt firmware and complete image, and retain
physical startup and watchdog reset as explicit bench acceptance.

## Findings

The shipped control FDT has an enabled `/soc/watchdog@2ace0000` with tclk/pclk.
The RK3576 clock provider has no enable callback; non-CCF `clk_enable` returns
-ENOSYS, and DesignWare probe propagates it. This reproduces as -38 using the
actual pinned DesignWare source and clock ops. The new RK3576 callback opens
CRU_CLKGATE_CON16 bits 7 and 8 before watchdog MMIO access. Unknown clock IDs
retain their prior unsupported result.

The regression passes with the patch, including probe, clock gates, arm/feed
registers and unrelated-clock refusal. Actual firmware policy fixtures also
verify that probe/start errors enter recovery before media reads or trial writes.
The build now runs this driver regression and checks the shipped control FDT.
No watchdog requirement, signature policy or compatibility path is relaxed.

Evidence: `.tmp/cx-watchdog/red.log` (probe -38, exit 134), `green.log` (exit 0).
The initial test compilation exposed the upstream unused `flags` parameter;
its warning handling is aligned with the upstream build before establishing RED.
Clock gates are cross-checked against the official RK3576 Linux clock driver:
https://raw.githubusercontent.com/rockchip-linux/kernel/develop-6.1/drivers/clk/rockchip/clk-rk3576.c
