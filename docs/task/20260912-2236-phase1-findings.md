## Description

The Phase 1 proof of `20260911-2003-split-package-repositories` (pool built
through the lock, x64 composed from a fetched `mos-podman`, image verified)
ran into seven defects that predate the split and were worked around rather
than fixed. Fix each at its cause; none belongs to the split itself.

1. `boards/s905x5m/bsp/Makefile` `userland` runs `docker buildx build
   --platform linux/arm64` on the ambient builder, which on a host without
   binfmt is `default` and dies with `exec format error` inside
   `s905x5m-bluetooth`'s PREPARE hook. `build-env/deb/build.sh` selects the
   emulating `mos-arm64` builder itself; the BSP target must do the same.
2. `tests/deb-package-gate.sh` refuses the arm64 pool: `mos-board-cx3576`,
   `mos-board-s905x5m` and `mos-board-virt-arm64` all own `/etc/fstab`,
   `/etc/repart.d/*.conf` and the `systemd-repart.service.d/10-data.conf`
   drop-in, and declare no mutual `Conflicts`, so the gate's one exemption
   does not apply (293/295 on 2026-09-12). Three board packages in one pool
   are mutually exclusive by construction; say so in their control templates.
3. `verify`'s `file-root-native-endpoints` check attributes a diagnostic URL
   by the exact merged-string bytes that follow it in the binary. Its
   allowlist did not match the tree's own `mosd`, `apid` and `mos-deploy`
   (the same layouts at `a6b7b55c` and at `407ac055`), so `os-verify` was red
   for every image until four followers were attested during the proof. The
   attestation must either be generated from the archives at build time or
   the check must attribute by the source string alone.
4. `rootfs/build.sh` defaults `MOS_META_DIR` to `meta/`, which
   `validate-public-meta.sh` refuses (`boot`, `verity` are not public
   entries); every pipeline creates a `public-meta` copy by hand. The
   composer should derive the public subset (`updates/manifest.json`,
   `GENERATED`) itself, or the documented default must be a directory that
   validates.
5. `tests/shell-pipefail-lint.sh` reports `pkgs/mos-boot/init-keys.sh:63` and
   `pkgs/mosd/apid/ui/verify-ui-policy.sh:82` (an early-exiting `grep` on the
   right of a pipe under `pipefail`).
6. Two suites were red in a way the split's changes did not cause but did
   reveal: `os-deb-package-gate` never reaches its reproducibility rebuild
   while (2) fails, and `os-verify` was not part of any green record after
   (3) landed on 2026-09-10.
7. `tests/factory-root-gate/gate.sh` finds the packed root and the OCI
   export identical on all five comparisons, then fails its fifth negative
   case: the composition ships no character device (they are captured and
   never shipped, by design), so "the device comparison has nothing behind
   it" and the gate exits 1 on a correct root.

Acceptance: `make os-deb-package-gate`, `make os-verify` and
`make os-factory-root-gate` for an x64 image,
`bash tests/shell-pipefail-lint.sh` and `MOS_BOARD=x64 bash rootfs/build.sh`
with no `MOS_META_DIR` are green on a clean checkout; `make os-deb-s905x5m-bluetooth`
succeeds on a host without binfmt.
