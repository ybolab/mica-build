# RFCT-275 Make the built-in UI a pure SPA over the management API

- **status**: completed
- **priority**: P1
- **owner**: codex/spa-api-boundary-20260831
- **createdAt**: 2026-08-31 15:40
- **plan**: [PLAN-039](../plan/PLAN-039.md)

## Description

apid currently mixes a server-rendered HTML control plane with the JSON API:
routes such as `POST /containers/enable` mutate the appliance outside `/api`,
while the built-in fallback is generated by Rust handlers rather than served
as a standalone application.

Move the shipped UI to an explicit `/ui` SPA. The device root selects an
active custom UI when one exists and otherwise enters the built-in `/ui`; the
built-in application is static client code and performs every read, write,
authentication and action through `/api`. Remove the legacy HTML mutation
surface. Expand the network view so it inventories the current interfaces and
shows each interface's observed runtime state, not only its stored settings.

## Acceptance

- `/` selects the active custom UI when one is valid and otherwise enters the
  built-in UI at `/ui`.
- `/ui` and its asset subtree always serve the shipped built-in SPA and cannot
  be shadowed by a custom bundle.
- No appliance read, write, authentication operation or action is implemented
  by a non-`/api` route; legacy routes such as `/containers/enable` are gone.
- The SPA uses relative `/api` calls and contains no server-rendered form
  action or backend business handler.
- Setup, login, logout and authenticated API access have one JSON contract
  usable by both the built-in and custom SPAs.
- The network screen reports the number of interfaces and each interface's
  configured kind plus observed operational status, addresses and link state
  when available.
- OpenAPI, Rust tests, SPA tests/build, package assembly and the affected e2e
  phases agree with the shipped route and authentication contracts.

## ActiveForm

Separating the built-in SPA from the API-only management backend.

## Dependencies

- **blocked by**: (none)
- **blocks**: UI work that assumes `/ui` is a static SPA or that non-API form routes do not exist
