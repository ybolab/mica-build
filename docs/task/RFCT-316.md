**Recommendation:** adopt explicit non-capabilities for field credential recovery, full factory reset, secure wipe, rescue/offline repair, sealed images, META lockdown, permanent lockout, comprehensive session audit/upload, and the three local setup front ends. Retain the narrower capabilities that the code actually provides. Guarded rollback already provides an explicit two-action operator workflow; close its partial label editorially instead of adding an automatic reboot.

Of the **30 claim-bearing occurrences**, **2 recommend complete** (the same existing rollback capability, counted twice) and **28 recommend downgrade**. Five legend occurrences require no capability decision. This is not a vote to remove working reset, profile, audit, AP, or provisioning code: each aggregate downgrade identifies what remains supported and what is unavailable.

Estimates are engineering effort after approval, in person-days; `0 code` means the implementation of the explicitly bounded capability already exists. Estimates exclude hardware qualification and do not imply anything was executed in this task. Compatibility work is not required.

## Source evidence

These references name executable bodies, declarations, and package inputs rather than relying on their explanatory comments. The absence findings also use the route table, reconciler registration, model fields, and package/unit inventory; a missing symbol alone is not treated as proof.

- **E1 — Reset vocabulary, staging, and reachability.** [model.rs](../../pkgs/mosd/mosd-settings/src/model.rs#L694), `ResetSettings` and `ResetTier`, admit exactly configuration/application-data/full-factory. [routes.rs](../../pkgs/mosd/apid/src/routes.rs#L6139), `api_v1_reset`, authenticates every request, checks presence for full-factory, writes one `reset` record, and reports next-boot application. Generic settings writes use an explicit scalar allowlist (`writable_shape`, line 2014); it does not permit writing `reset`. [reset-panel.tsx](../../pkgs/mosd/apid/ui/src/features/recovery/reset-panel.tsx#L22) offers only the first two tiers. There is no secure-wipe variant.
- **E2 — Actual reset effects and durability boundary.** [reset.rs](../../pkgs/mosd/mosd/src/reset.rs#L188), `apply_pending`, `reseeded_settings`, and `clear_application_state`: configuration resets the settings tree while preserving provisioning identity, device credentials, web administrator, claim and API tokens; application-data clears STATE `quadlet`/`systemd-units`, DATA `mos/apps`/`mos/containers`, and `srv`; full-factory additionally empties the `/mos` skeleton and drops management access settings. It does **not** clear all STATE. [mos-seed-state](../../rootfs/overlay/usr/lib/mos/mos-seed-state#L39) preserves existing STATE content, including Bluetooth pairing data, and [var-lib-mos.mount](../../rootfs/overlay/etc/systemd/system/var-lib-mos.mount) exposes retained daemon state. `reset.rs` has no filesystem/directory sync after deletion; [Store::save](../../pkgs/mosd/mosd-settings/src/store.rs#L238) syncs the settings file and its parent, not the separate DATA filesystem. See F1–F2.
- **E3 — Presence mapping and board absence.** [shared recovery module](../../pkgs/mosd/mosd-settings/src/recovery.rs), `Declaration::read/parse/map_intent`, and [boot recovery module](../../pkgs/mosd/mosd/src/recovery.rs#L105), `apply_boot_intent`, map a declared `mos.recovery=` token, write a marker, optionally stage a tier, and audit. [main.rs](../../pkgs/mosd/mosd/src/main.rs#L218) calls this before reset and provisioning. [cx3576 board.env](../../boards/cx3576/board.env#L512) and [x64 board.env](../../boards/x64/board.env#L355) both set `BOARD_RECOVERY_ACTIONS=""`; neither boot script supplies a recovery intent or a recovery menu. The DTS [disables adc-keys](../../boards/cx3576/bsp/kernel/dts/rk3576-cx3576z.dts#L267). [MarkerPresence](../../pkgs/mosd/apid/src/routes.rs#L5974) reads the declaration first, rejects none/unreadable/unknown/expired assertions, and never consumes an assertion. The schema exists; the field entry does not.
- **E4 — Credential rotation exists, with narrower guarantees.** [api_v1_recovery_credential](../../pkgs/mosd/apid/src/routes.rs#L6243) rejects an authenticated caller and an unclaimed device; mints and hashes a password; publishes it to the marker channel before committing `access`; empties API tokens, preserves claim provenance, bumps generation, invalidates the access cache and all browser sessions, and clears the login guard only after success. [SessionStore::remove_all_except](../../pkgs/mosd/apid/src/session.rs#L151) confirms session revocation. Publication rejects regular files and flushes the opened channel. There is no one-use marker consumption or recovery serialization, and some early failures have no recovery audit event. [credential-recovery-panel.tsx](../../pkgs/mosd/apid/ui/src/features/recovery/credential-recovery-panel.tsx) offers no action. See F3–F5.
- **E5 — Manual rollback is an existing two-action interface.** [rollback_eligibility](../../pkgs/mosd/mosd/src/rauc.rs#L458) checks the alternate slot, bad/never-installed status, timestamp order and unconfirmed boot. [api_v1_update_rollback](../../pkgs/mosd/apid/src/update_api.rs#L440) reads that verdict, marks only `bad`/`booted`, audits, and returns `nextStep: POST /api/v1/actions/reboot`; it does not dispatch reboot. [rollback-panel.tsx](../../pkgs/mosd/apid/ui/src/features/system/rollback-panel.tsx#L42) renders eligibility/refusals and tells the operator to reboot after success. [api_v1_reboot](../../pkgs/mosd/apid/src/routes.rs#L6804) dispatches a separate power request; [bus.rs](../../pkgs/mosd/mosd/src/bus.rs#L465) enforces the reboot interlock. HTTP 202 acknowledges dispatch, not reboot completion. Timestamp-derived eligibility is not a direct confirmed-boot history or hardware fallback evidence.
- **E6 — Boot failure handling and physical reflash.** [cx3576 boot.cmd](../../boards/cx3576/boot.cmd#L73) refills exhausted counters and resets; missing verity data or returned `booti` burns the slot's remaining credit and resets. [x64 grub.cfg](../../boards/x64/grub.cfg#L151) retries selection in `ORDER` when no slot qualifies, but contains no unconditional reboot instruction or rescue environment. [BSP Makefile](../../boards/cx3576/bsp/Makefile#L97), `flash`/`flash-maskrom`, writes the full image with `wl 0`, verifies the boot area, and resets; maskrom first downloads the pinned loader. [mkimage-cx3576.ts](../../build/src/mkimage-cx3576.ts#L373) creates fresh META/STATE/DATA filesystems and places them in the disk image. [identity::ensure_identity](../../pkgs/mosd/mosd/src/identity.rs#L103) mints identity/secrets when absent. Reflash is not medium sanitization; no hardware acceptance is inferred from these inputs.
- **E7 — Repair primitives, not a repair product.** [mos-data-layout](../../rootfs/overlay/usr/lib/mos/mos-data-layout) creates missing skeleton directories, enforces modes, rejects symlinks, and probes/syncs the writable pool. [storage_status.rs](../../pkgs/mosd/mosd/src/storage_status.rs#L625), `LIFECYCLE`, explicitly reports `offlineRepair`, `factoryReset`, `secureErase`, and `backupRestore` as unsupported; its fsck reader reports boot-time checker evidence. RAUC installation in [rauc.rs](../../pkgs/mosd/mosd/src/rauc.rs), `install_bundle`, uses the normal installer, not a repair route. No dedicated rescue boot entry, repair endpoint, or mounted-filesystem repair action appears in the boot/route/package inventory. The BusyBox [package](../../rootfs/packages-src/busybox/Dockerfile) and [common package input](../../rootfs/packages/common.pkgs#L15) provide an ordinary dynamically linked `/usr/bin/busybox`, not a second bootable userspace.
- **E8 — Access model and runtime SSH.** [AccessSettings/SshSettings/ConsoleSettings](../../pkgs/mosd/mosd-settings/src/model.rs#L305) have no `idleTimeout`, `autoDisableAfter`, configurable brute-force block, lockdown bit, PIN/challenge-response fields, or general `requirePhysicalPresence`. The console flag exists but [reconciler registration](../../pkgs/mosd/mosd/src/reconciler/mod.rs) has no console-shell consumer. [sshd.rs](../../pkgs/mosd/mosd/src/reconciler/sshd.rs#L339) renders keys/config and starts/stops and enables/disables SSH; password authentication also requires the transient password marker. The transient root password is implemented separately in [transient.rs](../../pkgs/mosd/mosd/src/transient.rs); it is not a timed SSH auto-disable or a wizard credential.
- **E9 — Two image profiles already exist.** [profile package Dockerfile](../../rootfs/packages-src/profile/Dockerfile#L53) emits exactly dev/prod `profile.conf` files, mode 0444; [dev package input](../../rootfs/packages/profile-dev.pkgs) and [prod package input](../../rootfs/packages/profile-prod.pkgs) select them. [read_profile](../../pkgs/mosd/mosd/src/provisioning.rs#L179) falls back to prod; both seed SSH off. There is no sealed package/profile selection. The SSH reconciler and [STATE SSH seeding](../../rootfs/overlay/usr/lib/mos/mos-seed-state) remain in the product. The current profile writer is the package, not the design document's old direct `rootfs/build.sh` writer.
- **E10 — Bounded backoff and local audit.** [auth.rs](../../pkgs/mosd/apid/src/auth.rs), `LoginGuard`/`GuardStore`, charge admission under a lock, persist failure/deadline state, cap backoff at 300 seconds including load, and start clean on unreadable/corrupt state. There is no permanent threshold. [apid Audit::record](../../pkgs/mosd/apid/src/audit.rs#L61) mirrors to the journal and swallows persistence failure; [shared audit writer](../../pkgs/mosd/mosd-settings/src/audit.rs#L71) rotates two 256 KiB files and fsyncs each line. This is apid login protection, not an SSH/PAM brute-force control.
- **E11 — Some session events already exist; comprehensive lifecycle/upload does not.** [session creation/deletion handlers](../../pkgs/mosd/apid/src/routes.rs#L864) record successful browser login and explicit logout; recovery records outcomes and invalidates sessions. [session.rs](../../pkgs/mosd/apid/src/session.rs#L96) expires/removes entries in memory without a duration/termination audit record. The audit sink only writes local files and tracing; it has no network exporter or session inventory. SSH session open/close and presence-check histories are not furnished as a comprehensive audit capability.
- **E12 — Provisioning transport and claim policy.** [mos-provisioning-import](../../rootfs/overlay/usr/lib/mos/mos-provisioning-import) stages the fixed TOML filename from boot partitions first and removable media second, using read-only mounts. Its [oneshot unit](../../rootfs/overlay/etc/systemd/system/mos-provisioning-import.service) orders it before mosd and retains mounts; there is no hotplug import. [provisioning_doc.rs](../../pkgs/mosd/mosd/src/provisioning_doc.rs#L373) validates the entire document, recognizes an unchanged digest, refuses a different document on a claimed device, and saves accepted settings once. There is no signature-verification branch. Normal network claim/setup exists in [routes.rs](../../pkgs/mosd/apid/src/routes.rs), `api_v1_setup`; it is not a lockout bypass.
- **E13 — AP plumbing is real; the promised local setup channels are absent.** [WifiApReconciler](../../pkgs/mosd/mosd/src/reconciler/wifi_ap.rs) renders hostapd and networkd DHCP/address configuration and operates the AP service. The registered reconcilers include it. The route/UI implementation supplies ordinary browser setup. The source/package/unit inventory contains no captive-portal interception/redirect service, HDMI kiosk browser launcher with a local setup flow, or tty2 wizard/PIN verifier. AP networking is therefore not evidence that any of those three interfaces ships.
