# UI-002 Design the local application lifecycle module

- **status**: completed
- **priority**: P1
- **owner**: codex/app-module-20260901
- **createdAt**: 2026-09-01 21:30

## Description

Define how the built-in UI and management plane could discover, install,
manage, update and remove local applications. The design must cover both OCI
container applications and native program-plus-systemd-unit applications,
while separating an optional curated application catalog from device-local
lifecycle management.

## Acceptance

- The current native package, Quadlet, D-Bus item and API seams are inventoried.
- One common application model and lifecycle are proposed for both artifact
  types without treating arbitrary systemd units as user applications.
- Catalog trust, signing, compatibility, storage, rollback, permissions,
  secrets, logs and failure behavior have explicit owners.
- The built-in UI information architecture, page states and required typed API
  surface are defined.
- Scope boundaries and staged delivery distinguish local management from a
  remote public marketplace.

## Notes

- 2026-09-01: The current product has no `/api/v1/apps` or catalog API. The
  built-in Services page only controls the global `container.enabled` and
  `mqtt.enabled` settings.
- 2026-09-01: Container delivery currently means rootful Podman plus persistent
  Quadlet definitions. Image admission accepts unsigned content, automatic app
  update/rollback, mandatory resource ceilings and an application secret store
  do not exist.
- 2026-09-01: Native OS-integrated applications are immutable build-time `.deb`
  inputs and update with RAUC. A writable STATE-backed systemd unit directory
  exists for trusted integrators, but arbitrary persistent units fall outside
  the signed root and can outlive an incompatible A/B rollback.
- 2026-09-01: `mosd`'s `services` live-state registry discovers `com.mos.*`
  processes and their conformance, but it is not an installed-application
  registry: one app may own several services, and an app need not expose
  `com.mos.Item1` at all.
- 2026-09-01: PLAN-051 deliberately excludes a marketplace and requires a new
  plan if managed/untrusted admission is promised. PLAN-056 is that separate
  proposal rather than a silent expansion of PLAN-051.
- 2026-09-01: No repository design-system manifest exists. A future prototype
  should use the shipped SPA's existing tokens and components as its binding
  visual context.
