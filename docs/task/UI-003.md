## Description

Produce one self-contained Chinese Markdown guide for product and UI designers.
It must inventory both shipped and planned built-in-device functions, define
the intended interactions and prototype coverage without implementation detail,
and make clear that production development may capability-gate unfinished
screens.

## Acceptance

- The guide is written for designers, not frontend or backend implementers.
- One coherent information architecture covers current and planned functions,
  including the approved Applications module.
- Every screen has a purpose, content/actions, critical states and maturity.
- Cross-product journeys, interaction patterns, responsive/touch behavior,
  accessibility, language and prototype expectations are explicit.
- Planned screens can be designed and prototyped without being mistaken for
  shipped product; the implementation handoff explains capability gating.
- The only design-guide delivery artifact is Chinese Markdown at
  `docs/zh/design/built-in-ui-design.md`; no `designs/` HTML artifact remains.

## Risks

- Planned concepts may be read as product commitments unless maturity is
  visible at both the feature map and screen brief.
- A comprehensive guide may become an undifferentiated settings inventory;
  workflows and operator outcomes must remain primary.
- Prototype exploration can invent capabilities without owners. Reserved
  concepts need explicit decision or dependency labels.

## Scope

In scope: product structure, current and planned functional inventory, screen
briefs, critical user journeys, component/state language, responsive and
accessibility direction, prototype expectations and developer handoff gates.

Out of scope: source layout, API method tables, frontend architecture, build
commands, production implementation and HTML prototype delivery.

## Alternatives

1. Keep extending the developer guide. Rejected because design intent and
   implementation constraints serve different readers.
2. Describe only shipped screens. Rejected because designers must plan coherent
   future flows before each backend slice lands.
3. Deliver an HTML prototype now. Superseded by the user's Markdown-only
   direction.
