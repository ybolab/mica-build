# UI-006 Move the built-in UI to `/_ui/`

- **status**: completed
- **priority**: P1
- **owner**: codex/builtin-ui-prefix-20260902
- **createdAt**: 2026-09-01 23:58

## Description

Move the built-in recovery SPA from the public `/ui` namespace to `/_ui/` so
an active custom UI can own `/ui` and its descendants without colliding with
APID's built-in router. Preserve terminal ownership between the custom root,
the built-in namespace and `/api`, and migrate the frontend base, generated
assets, tests and current documentation as one public-route change.

## Acceptance

- `/_ui`, `/_ui/` and descendants are served only by the compile-time built-in
  VFS, with `/_ui/` used as the canonical generated base and root redirect.
- `/ui` has no built-in alias, redirect or reserved-root behavior; an active
  custom bundle can serve `/ui` and files below it through the normal root
  asset and SPA fallback rules.
- Encoded, repeated-separator and hostile aliases cannot cross the `/api`,
  `/_ui` and custom-root ownership boundaries. The logical-path guard reserves
  `_ui`, not `ui`.
- Vite, TanStack Router, navigation state and the English/Simplified Chinese UI
  copy use the new recovery address, and the committed `dist` tree is rebuilt.
- Rust route/path tests, frontend gates, APID e2e coverage and current English
  and Chinese product/development documentation describe the new namespace.
- `/api/v1/ui`, `/srv/ui`, custom UI activation, `/healthz`, authentication,
  theming and the shadcn/Base UI/Spectrum component boundary remain unchanged.
