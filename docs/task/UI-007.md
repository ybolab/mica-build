# UI-007 Add uploadable versioned custom UI packages

- **status**: completed
- **priority**: P1
- **owner**: codex/ui-package-upload-20260902
- **createdAt**: 2026-09-02 00:25

## Description

Let an authenticated operator upload a packaged custom UI from the built-in
console, retain multiple validated versions under `/mos/ui`, select an exact
version, return to the built-in UI, and delete inactive versions. Provide a
deterministic host-side packaging and inspection tool for integrators.

## Acceptance

- A bounded raw ZIP upload is streamed to a private staging file, safely
  extracted and validated without buffering the archive in APID memory or
  allowing traversal, symlinks, special files, duplicate names or ZIP bombs.
- Upload writes only to PLAN-061's verified writable `/mos/ui` DATA subtree and
  never falls back to another filesystem when that workspace is unavailable.
- Uploaded packages require a versioned `mos-ui.json`, a root `index.html`, API
  compatibility and the existing tree safety/digest checks; installation is
  atomic and does not automatically change the active UI.
- The API lists every retained generation, activates an explicitly selected
  usable generation, deactivates to built-in and deletes only inactive ones.
- Multiple versions remain until explicit deletion or a refused capacity
  bound; installation no longer silently prunes operator-selected versions.
- The built-in `/_ui/` System UI provides accessible upload progress,
  validation results, version selection, activation/deactivation and delete
  confirmation while the recovery UI remains available throughout.
- A standalone `mos-ui-pack` tool creates deterministic `.mos-ui.zip` files,
  validates the same manifest/path contract and can inspect a package before
  upload.
- Authentication, browser CSRF, audit records, OpenAPI, Rust/frontend/e2e
  tests, packaging-tool tests and current design/development/user docs cover
  the complete lifecycle.
