# UI-010 Isolate built-in UI build outputs

- **status**: completed
- **priority**: P1
- **owner**: ui-container-build/session-20260902
- **createdAt**: 2026-09-02 20:34

## Description

Make the built-in UI a container-only producer. Mount its source read-only,
keep the copied build workspace and generated asset tree under repository
`_out/`, and let Rust build containers consume those assets through a separate
read-only mount while writing Cargo output outside the source tree.

## ActiveForm

Isolating built-in UI build outputs.

## Acceptance

- The UI production and quality entries always use the repository-pinned Bun
  container and never select a host Bun installation.
- The UI source mount is read-only; dependency installation, generated route
  files, compiler metadata and Vite output are confined to `_out/apid-ui/`.
- The fixed production tree is `_out/apid-ui/dist`, remains untracked, and is
  the only UI tree passed to APID Cargo builds.
- Rust target and package build containers mount repository source read-only,
  mount Cargo target directories separately as writable, and mount the UI
  production tree read-only.
- Contract tests, frontend gates, focused APID tests and relevant documentation
  describe and verify the container-only producer boundary.
