# UI-012 Align the built-in console with the approved prototype details

- **status**: completed
- **priority**: P1
- **owner**: ui-detail/session-20260902
- **createdAt**: 2026-09-02 21:20

## Description

UI-008 rebuilt the built-in console from the approved prototype
(`docs/zh/design/mos-ui/project/index.dc.html`) but reproduced it only in
outline. The shipped visual system still diverges from that prototype in
tokens, type scale, density, chrome geometry, breakpoints and control shapes,
so the console does not read as the approved design. Close those detail gaps
without changing the information architecture, the API bindings or the
simulation boundary.

## ActiveForm

Aligning the built-in console with the approved prototype details.

## Acceptance

- Light and dark themes carry the prototype's Klein palette, including the
  hover, accent-soft, accent-strong, skeleton and chrome roles, and the header
  chrome uses the prototype's chrome/active/logo colors in both themes.
- The type scale matches the prototype: 22px page titles and 16px section
  titles in the body face, 13px secondary copy, 15px table and control text,
  and 13px footer text.
- The header, footer and mobile drawer reproduce the prototype's geometry:
  56/52px header, square logo mark with the stacked wordmark and hostname,
  rounded navigation pills with an inverted active state, 36px icon actions,
  a 44px footer on the page ground, and a 300px drawer with a status block.
- Buttons, inputs, tags, tables, tab strips, switches, dialogs, progress bars
  and skeletons match the prototype's sizes, radii, weights and states, and
  the sign-in card keeps its blueprint frame.
- Breakpoints, container width, page padding and the section/metric grids
  follow the prototype's compact/medium/wide behavior.
- Frontend lint, typecheck and unit gates pass through the pinned builder, and
  the Playwright appearance baselines are regenerated.

- complete: prototype detail alignment shipped
