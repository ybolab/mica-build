# UI-013 Complete the built-in console against the prototype information architecture

- **status**: in_progress
- **priority**: P1
- **owner**: ui-ia/session-20260902
- **createdAt**: 2026-09-02 22:30

## Description

UI-012 closed the visual gap to the approved prototype
(`docs/zh/design/mos-ui/project/index.dc.html`) but explicitly left content and
information architecture alone. Every page still differs from the prototype in
what it shows and how it is navigated: page headers carry descriptions the
prototype does not have, Network edits happen in a dialog rather than an
interface detail route, Services has no detail view or per-service
configuration, Applications is missing filters and the Desired column, Access
is not laid out as labelled sections, and System carries seven tabs against the
prototype's six.

Bring each surface to the prototype's structure, states and copy, keeping every
existing device binding on its real API and putting only genuinely unavailable
capabilities behind the existing labelled simulation layer. Surfaces the
product ships that the prototype has no place for are retained as explicitly
marked extra sections rather than deleted.

## ActiveForm

Completing the built-in console against the prototype information architecture.

## Acceptance

- The shell matches the prototype: no page-level description, a status tag and
  freshness in the page header, release and active slot in the footer, a
  spinning refresh affordance, a connection banner off the happy path, and a
  settings menu holding a searchable language picker and a segmented theme
  control.
- Overview shows the attention count as a label above its card, tagged
  attention rows with a trailing action, four navigating summary cards with
  monospace identifiers, and the action/target/phase/result/time task table.
- Network merges observed state into the interface table, opens an interface
  detail route with overview, addressing and danger sections, and applies
  changes through the review dialog and apply progress strip. Known Wi-Fi and
  WireGuard match the prototype's tables, summary cards and rotation panel.
- Services lists cards with a header switch and opens a service detail route
  with configured/observed/endpoint cards and per-service configuration. The
  terminal service opens the prototype's terminal window with minimize,
  fullscreen and close.
- Applications gains the source and kind filters, the retained-data count, the
  Desired column, the container-runtime-disabled banner, the prototype's
  catalog fields and its four-step install wizard.
- Access is laid out as labelled sections for the web administrator, API
  tokens, SSH and the root password, with the token reveal, its close
  confirmation and key removal confirmation.
- System has the prototype's six tabs and rebuilds General, Information, Time,
  Update & recovery, Storage and Diagnostics, including the update step strip,
  the check table, automatic-update policy, manual upload, configuration
  backup, the storage breakdown and the support PIN flow.
- The prototype's dialogs exist: reboot, power off, interface review, close
  reveal, remove key, request support, restore configuration, remove UI
  package, rotate WireGuard key, install update, and the typed factory-reset
  challenge. Saves confirm with the prototype's toast.
- Loading, empty, error, offline and unsupported states follow the prototype,
  including its skeleton rows.
- Surfaces without a prototype home (observed routes, device claim,
  provisioning document, credential recovery, reset tiers, rollback, package
  manifest, telemetry) remain reachable and are marked as additions.
- Every capability without a device API stays inside the shared simulation
  layer and keeps its localized notice; no new page invents a device fact.
- Frontend lint, typecheck and unit gates pass through the pinned builder, and
  the Playwright baselines and flows are regenerated.
