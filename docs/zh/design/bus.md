## 1. D1 —— 唯一的 item 接口 `com.mos.Item1`

每个 `com.mos.*` 服务——先是 mosd，之后是扩展服务——对可寻址的值**只讲一个 D-Bus 接口**。
**没有第二个数据面接口**：一个能读、能写、能订阅 item 的消费者，就能消费总线上的每一个服务。
正是这条性质让 MQTT 桥成为一个纯粹的边缘组件。

### 1.1 接口定义

```xml
<interface name="com.mos.Item1">
  <!-- 每个 item 对象路径上 -->
  <method name="GetValue"> <arg direction="out" type="v"/> </method>
  <method name="SetValue"> <arg direction="in" type="v"/>
                           <arg direction="out" name="result" type="i"/> </method>
  <!-- 仅服务根对象路径 "/" 上 -->
  <method name="GetItems"> <arg direction="out" type="a{sa{sv}}"/> </method>
  <signal name="ItemsChanged"> <arg type="a{sa{sv}}"/> </signal>
</interface>
```

`GetValue` / `SetValue` 存在于**每一个 item 对象路径**上——一个 item 一个 D-Bus 对象，
在认领知名总线名之前就注册好，并由驱动 `ItemsChanged` 的同一个变更监视器保持同步。

**结果码词汇表**，一个结果一个码：

| 码 | 含义 |
|---|---|
| `0` | 设置写入已生效，或动作已派发 |
| `-1` | 该路径上没有 item —— 包括被结构性脱敏掉的（见第 8 节） |
| `-2` | item 存在但不可写 |
| `-3` | 值与 item 的类型不匹配 |
| `-4` | 设置写入**通过了校验但不会持久化** |
| `-5` | 动作**被接受但不会派发** |

正数返回值**保留**，不得产生。

## 7. D3 —— 动作就是可写的 item

- 动作是 `/Actions/<verb>` 下的一个 item。它的值**永远读作 `0`**——这是常量，不是存储值。
- **`SetValue` 触发动作，且任何写入值都触发**：写入本身就是触发器，所以值被接受并忽略。
  服务在写入后把值强制回 `0`，并且**即使是 `0 -> 0` 这条边也发出变更信号**——
  强制归零是可观测的，于是订阅者能看到每一次触发的消费边。
- 由于值是常量，任何两次投影的差分都不可能携带这条边；实现把它注入到**与该请求的实时状态记录
  同一个合并后的 `ItemsChanged` 批次**里，所以这条边不额外花费一个信号。
- **`SetValue` 的返回码就是派发结果**：`0` 表示已接受并派发，负码表示没有。
  `-5` 之所以存在，正是为了让「已接受但不会派发」不被误认成「设置写入没有持久化」。
- 完成度与进度（如果有）是树里别处的普通 item，**动作 item 自身不携带状态**。
- 既有的安全性质通过**复用**而非重述来保持：派发调用既有的 `request_reboot` /
  `request_power_off`，所以电源请求的追踪日志与实时状态记录仍然写在电源调用**之前**。

## 8. 结构性脱敏是总线级契约

被脱敏的 item **不是读作空值，而是根本不在树里**——所以它的路径回答 `-1`（没有该 item），
而不是回答一个空字符串。

## 11. 已发布 item 树的已知限制

六条性质，读者不看就会撞上。每一条都是**带理由的决定**，并写明什么会改变它。

1. **未知对象路径返回 D-Bus `UnknownObject` 错误，而不是 `-1`。** 这不是 1.1 节词汇表的缺口，
   而是词汇表够不到的地方：zbus 按**精确**对象路径派发，没有子树或兜底处理器，
   所以要在任意路径上回一个返回码，就得在客户端可能猜到的每个路径上都注册对象——一个无界集合。
   而且 `SetValue` 的契约**本身就是方法返回码**，没有对象时也就没有方法可供返回。

## 关于平台开关

`container.enabled` 和 `mqtt.enabled` 这类平台开关在 item 树上**投影为只读**，
`SetValue` 回 `-2`，MQTT 的 `W` 主题也翻不动它们。它们只在 mosd 的 `SetSettings` 一个地方可写。
这是这一类开关的规则，不是某一个的疏漏。
