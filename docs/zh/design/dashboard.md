## 1. 问题与现状

`apid` 是一个 Rust crate，在 HTTPS 监听器上提供**十条路由**，加上 HTTP 监听器上一个兜底的 308
跳转路由。这就是全部 HTTP 表面：**没有嵌套路由器、没有兜底、没有静态资源路由**。

运维能看到的整个菜单是**四个链接加一个登出按钮**——状态（`/`）、网络（`/network`）、
主机名（`/hostname`）、电源（`/power`）。其中三个是编辑器，一个是状态页。

技术姿态是**测量出来的，不是假定的**：服务端渲染、编译期类型化的 HTML（`maud`）；
**整个仓库零 JavaScript**，由四项独立探测确认（没有 `<script` 标签、没有 `.js` 文件、
没有 `ServeDir`/`ServeFile`、没有 `fetch(`）；只有一份 7 行的内联样式表。

## 2. 着陆页仪表盘

### 2.1 着陆页遵守的规则

1. **只读。** 没有表单、没有控件、没有破坏性动作。每个磁贴链接到做对应改动的那个页面。
2. **每个磁贴回答一个运维真的会问的问题**，并且**用那个问题的措辞**。
   一个「因为数据正好有」而存在的磁贴，不满足这条规则。
3. **每个磁贴都有定义好的红色状态，以及该状态下定义好的下一步动作。**
   一个红了却没有下一步的磁贴是告警，不是仪表盘。
4. **绝不在运维会把它读成实际情况的位置上展示「配置意图」。**
   凡是 mos 只有配置值的地方，磁贴要在自己的标签里说清楚。
5. **底层子系统在这台设备上不存在的磁贴应当缺席，而不是显示为空。**
   「不存在」必须指**硬件或设置缺席**，**绝不能**指**协调器失败**。
6. **默认与服务端渲染兼容。** 每个磁贴都是请求时读取一个值并渲染进页面。
   除非明确标注，任何磁贴都不要求客户端传输通道。

每个磁贴都标注为 **(a) 今天就能做**（数据来源是已有的总线调用）或
**(b) 需要新的 mosd 工作**。

### 2.2 身份磁贴 —— 「我在看哪台机器？」

- **展示**：配置的主机名、设备身份（`deviceId`）、配置状态（`pending` / `complete`）。
- **数据来源**：`GetSettings("hostname")`、`GetSettings("provisioning")`。
- **可用性：(a) 今天就能做。** 身份是**设置**而不是实时状态，因此可达。
- **为什么它值得占据第一屏**：一个手上有多台一体机、或者浏览器里还开着昨天标签页的运维，
  首先需要知道**这是哪台机器**。

其余磁贴（网络、存储、更新、服务健康、电源）的定义见英文版。
